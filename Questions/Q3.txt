Business goal
Account management wants to know what a customer's profile looked like at a given time.

Input contract
Read all *.jsonl data files from every arrival_date folder under:
D:\Project_AI\PySpark_Hands_On\Input\landing\crm\customer_changes\
Reference: Input\crm_customer_changes.md
One delivered event per line; an event may be delivered more than once.

  event_id        STRING           Event identity.
  customer_id     STRING           Customer-profile identity.
  op              STRING           r = initial snapshot, c = create, u = update, d = delete.
  source_seq      BIGINT           Source commit order; higher means committed later.
  commit_ts       STRING           ISO-8601 UTC commit timestamp with milliseconds.
  effective_from  STRING           Business-effective date; not the version clock for this problem.
  changed_fields  ARRAY<STRING>    Changed attributes; an update with no changes has an empty array.
  before          STRUCT           Profile before the change; null for r/c.
  after           STRUCT           Profile after the change; null for d.

Both profile structs contain:
  segment STRING, account_manager STRING (nullable), city STRING, credit_limit INT, status STRING.
The explicit reader schema also includes a STRING field for retaining malformed JSON for counting.

An r event reports a profile already present at the starting snapshot. A c event reports a newly created profile.

Business rules
- Ignore malformed JSON lines and count them separately from duplicate deliveries.
- A repeated event_id counts once. Interpret each customer's events in source_seq order, not arrival order.
- Each r/c event starts a version with its after image.
- An update that changes attributes closes the open version and starts another with its after image.
- A no-change update creates no version and changes no validity date.
- A delete closes the open version but creates no output version. A later create may start another version.
- A version starts at its creating event's commit_ts and ends at the closing event's commit_ts.
- An unclosed version has valid_to_ts = null and is_current = true.
- Profile status is a source attribute; is_current describes whether that historical version is open.

Output contract
Unpartitioned Delta, overwrite current contents while preserving earlier versions.
Path:  D:\Project_AI\PySpark_Hands_On\Output\focused\FP-003_customer_profile_scd2

  customer_id          STRING

  city                 STRING
  credit_limit         INT
  status               STRING

  valid_from_utc_text  STRING      valid_from_ts rendered in UTC.

Both text columns use yyyy-MM-dd HH:mm:ss.SSS, correctly regardless of the session time zone.

Correctness checks, introduced individually
- Input lines reconcile to malformed lines plus valid deliveries; valid deliveries reconcile to unique events
  plus duplicate deliveries. Count no-change updates and deletes after event deduplication.
- At most one open version per customer; no open version for a customer whose final event is a delete.
- Versions follow source order and do not overlap. Adjacent versions meet except across a delete gap.
  Coincident start/end is allowed; an end earlier than its start is not.
- No-change updates leave dates unchanged. Replays do not change business results.
- Preserve profile attributes, nulls, required types and timestamp precision.
- UTC and IST text describe the same instant; IST wall-clock text is 5h30m later.
- Two builds produce identical rows, respecting duplicate multiplicity. Row counts alone are insufficient proof.
